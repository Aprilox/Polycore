# Polycore

**Multicore optimization for Minecraft.** Polycore spreads the game's work across every CPU core and ships with the
tools to measure the gain yourself. It starts with chunk generation; more areas will follow.

- Minecraft 1.21.1 · NeoForge 21.1.235+ · Java 21 (Fabric/Forge planned, see [docs/architecture.md](docs/architecture.md))
- Author: **Aprilox** · License: MIT
- **Singleplayer and servers.** Chunks are generated by the server; in singleplayer that server runs inside your game,
  so Polycore works there too. On a dedicated server, the server side is enough.

## Optimizations

| Optimization | What it does |
|---|---|
| **Dedicated worldgen pool** | Noise and biome computation run on Polycore's own threads instead of Minecraft's shared background pool, which also runs the generation queue and lighting. Never more threads than the machine has cores. |
| **Parallel surface & carvers** | In vanilla, every stage except noise and biomes runs on one queue, one chunk at a time. Surface and carvers only touch their own chunk, so Polycore runs them in parallel (same set of stages Paper/Moonrise parallelize). |
| **Parallel pre-generation** | Pre-generates an area with every core busy (cores × 8 chunks in flight, versus 32 for `/neoforge generate`). "Keep TPS stable" mode slows down automatically when the server lags. |

Measured on a 20-core machine (v0.1, radius 16): **28.6 → 67.4 chunks/s (+135%)**, average tick time 30 → 10 ms.

## The Polycore menu

Press **K** (or type `/polycore`). The menu has two sides:

- **This game**: overview (FPS, memory, connection) and your preferences (toasts, HUD overlay, refresh rate). Always
  editable, no operator needed.
- **Server**: dashboard with live graphs, optimizations, profiler, tools (pre-generation, benchmark, parity hash),
  reports and settings.

| Situation | What you get |
|---|---|
| Polycore on client and server | Full menu. `/polycore` opens it like the K key. |
| Singleplayer | Full menu, everything editable (you own the world, no cheats needed). |
| Server without Polycore | Client pages work; server pages say the server does not have Polycore. |
| Client without Polycore on a Polycore server | `/polycore` opens a chest-style menu made of vanilla items. |
| Not an operator | Read-only: stats, profiler and reports are visible, nothing can be changed. Operators can disable this (`permissions.allowNonOpView`). |

Feedback is shown as toasts (or in the action bar for vanilla clients), never in the chat. Players without the client
mod see task progress in a boss bar.

## Commands (alias `/pc`)

| Command | Access | Effect |
|---|---|---|
| `/polycore` | everyone (configurable) | Opens the menu (text summary in the console) |
| `/polycore status`, `stats`, `profiler`, `report` | everyone | Opens the matching page |
| `/polycore toggle <id> [true/false]` | operator | Enables/disables an optimization (saved) |
| `/polycore set <key> <value>` | operator | Changes any setting (saved) |
| `/polycore threads <n>` | operator | Pool size (0 = auto, max = logical cores) |
| `/polycore pregen start <radius> [concurrency]` / `stop` / `status` | operator | Pre-generation around you |
| `/polycore bench [radius]` | operator | A/B benchmark in fresh areas (use a test world) |
| `/polycore hash [radius]` | operator | Block fingerprint to check vanilla parity |
| `/polycore reload` | operator | Re-reads `config/polycore.json` |

## Configuration

- Server: `config/polycore.json` (pool, parallel stages, profiler, pre-generation, benchmark, permissions). Edited live
  from the menu, `/polycore set` or by hand followed by `/polycore reload`.
- Client: `config/polycore-client.json` (toasts, HUD, refresh rate).
- Reports: `polycore-reports/` (benchmarks and fingerprints).

## Compatibility

Works with Sodium, Lithium, FerriteCore, ModernFix. With **Moonrise** or **C2ME**, Polycore's generation
optimizations turn themselves off (they already rework the chunk system); the tools stay available.

## Building

```
gradlew.bat build        (Windows; run "set JAVA_HOME=" first if JAVA_HOME points to a missing folder)
./gradlew build          (Linux/macOS)
```

The jar is written to `build/libs/`. Test runs: `gradlew.bat runClient`, `gradlew.bat runServer`.

## Checking vanilla parity

1. Create a world with a fixed seed, `/tp @s 5000 120 5000`, then `/polycore hash 4`.
2. Recreate it with the same seed, disable the optimizations first (`/polycore toggle worldgen_pool false`,
   `/polycore toggle parallel_stages false`), same `/tp`, `/polycore hash 4`.
3. Both fingerprints must match.
