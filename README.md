# Polycore

**Multicore optimization for Minecraft.** Polycore spreads the game's work across every CPU core, and ships with the tools to measure the gain. Version 0.1 focuses on chunk generation; more areas will follow.

- Minecraft 1.21.1 · NeoForge 21.1.235+ · Java 21
- Author: **Aprilox** · License: MIT
- **Singleplayer and servers.** Chunks are always generated by the server; in singleplayer that server runs inside your client, so Polycore works there too. On a dedicated server, installing it on the server is enough. The in-game menu (key **K**) also needs the mod on the client.

## Features (v0.1)

| Feature | Type | What it does |
|---|---|---|
| Dedicated worldgen thread pool | Optimization | Terrain noise and biome computation run on a reserved pool (`cores - 2` threads). Minecraft's shared background pool, which also runs the generation queue (one task at a time) and lighting, is freed up. |
| Parallel pre-generation | Optimization + tool | `/polycore pregen start <radius>` requests `cores × 8` chunks at once (32 for `/neoforge generate`). Skips already generated chunks and saves regularly. |
| Stage profiler | Tool | Time spent in each chunk stage (structures, biomes, noise, surface, carvers, features, light…) plus pure computation time. |
| A/B benchmark | Tool | `/polycore bench` generates fresh areas far from spawn, first in "baseline" mode then in "Polycore" mode, and compares chunks/s, tick time and CPU. Report saved in `polycore-reports/`. |
| Parity hash | Tool | `/polycore hash` fingerprints the blocks of an area to check that an optimization does not change generated terrain. |
| In-game menu (key K) | Tool | Tabs: Optimizations (enable/disable), Live stats, Tools, Report. |

Planned for v2 (shown in the menu): parallel stage scheduler and SIMD terrain noise.

### Compatibility

- **Sodium, Lithium, FerriteCore, ModernFix…**: no known conflict.
- **Moonrise** or **C2ME**: the Polycore pool turns itself off (they already redirect the same calls). The profiler, pre-generation and benchmark stay active.

## Commands (operator, alias `/pc`)

| Command | Effect |
|---|---|
| `/polycore status` | List of optimizations and their state |
| `/polycore stats` | MSPT, TPS, CPU, memory, chunks/s, pool |
| `/polycore toggle <id> [true/false]` | Enable/disable (temporary) |
| `/polycore threads [n]` | Show/change the pool size |
| `/polycore profiler [reset]` | Time per stage |
| `/polycore pregen start <radius> [concurrency]` / `stop` / `status` | Pre-generate around you |
| `/polycore bench [radius]` | A/B benchmark (radius 10 by default) |
| `/polycore hash [radius]` | Block fingerprint (max radius 8) |
| `/polycore report` | Latest benchmark report |

## Configuration

`config/polycore-common.toml` (created on first launch): pool size and priority, profiler, pre-generation concurrency, benchmark radius. Toggles made in game are temporary; the config makes them permanent.

## Building

```
gradlew.bat build        (Windows)
./gradlew build          (Linux/macOS)
```

The first build downloads and decompiles Minecraft (5–15 minutes). The mod is written to `build/libs/polycore-<version>.jar`. If `JAVA_HOME` points to an invalid folder, clear it (`set JAVA_HOME=`) or point it to a Java 21 JDK.

Test runs: `gradlew.bat runClient` and `gradlew.bat runServer`.

## Checking vanilla parity

1. Create a world with a fixed seed, `/tp @s 5000 120 5000` (an ungenerated area), then `/polycore hash 4`.
2. Recreate the same world (same seed), run `/polycore toggle worldgen_pool false` first, then the same `/tp` and `/polycore hash 4`.
3. Both fingerprints must match. Per-chunk details are in `polycore-reports/`.
